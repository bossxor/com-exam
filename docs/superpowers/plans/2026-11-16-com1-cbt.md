# 컴활 1급 필기 CBT 구현 계획

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 한 문제씩 풀고 즉시 정답·해설을 보는 컴활 1급 필기 CBT를 웹앱(GitHub Pages + PC 로컬)과 안드로이드 앱으로 만들고, 기출·참고·AI 고난도 문제 약 1,140문항을 넣는다.

**Architecture:** 빌드 도구 없는 정적 웹앱(`web/`) 하나를 PC 로컬 서버, GitHub Pages, 안드로이드 WebView가 함께 쓴다. 계산 로직은 DOM 없는 `web/core.js`에 모으고 `node --test`로 검증한다. 문제집은 `addBank({...})`를 부르는 JS 파일 하나씩이고, 저작권 문제집은 git에서 제외해 로컬/APK에만 들어간다.

**Tech Stack:** HTML/CSS/vanilla JS (ES2020, 모듈 번들러 없음), Node 24 (`node:test`, 검증 스크립트), Python 3.14 + `pypdf`/`pymupdf` (PDF 변환), Kotlin + Android Gradle Plugin 8.x + Gradle 8.14.3 (캐시에 있음), GitHub Actions Pages.

**Spec:** `docs/superpowers/specs/2026-11-16-com1-cbt-design.md` — 모든 작업자는 이 계획과 함께 스펙을 읽는다. 장 번호(예: 스펙 8장)는 그 문서를 가리킨다.

## Global Constraints

- 작업 위치 `U:\` (네트워크 드라이브). Edit 도구가 `EBUSY: resource busy or locked, fchmod`로 실패하면 Write로 파일 전체를 다시 쓰거나 Python 스크립트로 고친다.
- 외부 CDN·프레임워크·npm 의존성 없음. 웹앱은 `file://`로 열어도, `http://localhost:8080`에서도, `https://bossxor.github.io/com-exam/`에서도 동작한다 (상대 경로만).
- 과목 코드: `0` 컴퓨터 일반, `1` 스프레드시트 일반, `2` 데이터베이스 일반. 보기 4개, `answer` 0~3.
- 합격 = 평균 60 이상 **그리고** 과목별 40 이상. 점수 = 정답 수 ÷ 출제 수 × 100, 소수 첫째 자리 반올림.
- 문항 ID = `${bank.id}-${n}`. 등록된 문제집의 `id`와 `n`은 바꾸지 않는다.
- 학습 기록 localStorage 키 `com1.v1`. 세트 기록은 최근 50개만.
- git 제외 (공개 저장소 `https://github.com/bossxor/com-exam`, 스펙 3장 A안): `pdf/`, `tools/src/`, `tmp/`, `dist/`, `web/data/kcci-*.js`, `web/data/ref-*.js`, `web/data/img/kcci-*`, `web/data/img/ref-*`. 푸시 전 매번 확인.
- 커밋은 팀장 세션만 한다. 팀원 세션은 파일을 만들고 보고만 한다 (같은 폴더 동시 커밋 충돌 방지).
- 파일 다운로드(폰트, 공개 기출 PDF)는 팀장이 파일명·출처·크기를 사용자에게 보여 주고 허락받은 뒤에만 한다.
- 문구는 스펙 10.1 "문구 원칙"을 따른다. 색·서체 토큰은 스펙 10.1 표의 값을 그대로 쓴다.
- 커밋 메시지 끝에 `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. 저장소 접근 실패(사생활 모드, `file://` 제한, 용량 초과) — `saveRecord`가 예외 없이 `false`를 돌려주고 화면에 "기록 저장 실패"가 뜬다. (Task 2 테스트)
2. 저장된 기록 JSON이 깨졌거나 `version`이 다름 — 앱이 죽지 않고 빈 기록으로 시작한다. (Task 2 테스트)
3. 필터 결과가 과목별 요청 수보다 적음 (예: 오답노트에 스프레드시트 3문항뿐) — 있는 만큼만, 중복 없이 뽑는다. 0문항이면 시작 버튼이 막힌다. (Task 2 테스트)
4. 이어서 풀기 대상 문항이 사라짐 (문제집 파일 삭제·이름 변경) — 남은 문항만 복구하고, 하나도 없으면 `current`를 지운다. (Task 2 테스트)
5. 학습 모드에서 보기를 빠르게 두 번 누름 — 기록이 한 번만 반영된다. (Task 2 테스트 `answer()` 두 번째 호출 `false`)

### Task 2: 핵심 로직 `web/core.js`

**Files:**
- Create: `web/core.js`
- Test: `tests/core.test.js`

**Interfaces:**
- Produces (브라우저 전역 `window.Core`, Node `module.exports` — 같은 객체):
  - `SUBJECTS: string[]` = `["컴퓨터 일반","스프레드시트 일반","데이터베이스 일반"]`
  - `TOPICS: {0:{[key]:name},1:{...},2:{...}}` — 스펙 6.1 표의 키·이름 그대로
  - `VISUAL_TAGS: string[]` = `["table","tr","th","td","div","span","b","i","br","code","pre","img"]`
  - `validateBank(bank) -> string[]` 오류 메시지 목록 (빈 배열 = 통과). 스펙 9.4 항목 중 파일 존재 검사를 뺀 전부 + `source==="ai"`이면 `verified===true` 필수.
  - `buildPool(banks) -> Q[]` — `Q = {...question, id, bankId, bankTitle, source}`; 입력 순서 유지.
  - `selectQuestions(pool, opts, rec, rng=Math.random) -> Q[]`
    - `opts = {bankIds: string[], subjects: number[], filter: "all"|"wrong"|"star"|"unseen", count: "all"|number, order: "original"|"random"}`
    - 순서: 과목 0→1→2로 묶는다. `count`가 숫자면 과목별 몫 = `floor(count/subjects.length)`, 나머지는 앞 과목부터 1개씩. 과목 안에서 `random`이면 섞고 앞에서 자르고, `original`이면 원래 순서로 앞에서 자른다.
    - `wrong` = `isInWrongNote`, `star` = `rec.q[id]?.star`, `unseen` = 기록 없음 또는 `tries===0`.
  - `isInWrongNote(r) -> boolean` = `!!r && r.wrong > 0 && r.streak < 2`
  - `applyAnswer(rec, id, choice, correct, now) -> void` — 스펙 8장 규칙 (`tries+1`; 정답 `streak+1`; 오답 `streak=0, wrong+1`; `lastChoice`, `lastAt`).
  - `score(questions, answers) -> {perSubject: {subject, correct, total, score}[], average: number, passed: boolean|null}` — 출제된 과목만 `perSubject`에, 미응답은 오답, 3과목 모두 있을 때만 `passed` 계산 (아니면 `null`).
  - `topicStats(pool, rec) -> {subject, topic, name, tries, correctRate, lowSample}[]` — 주제별 `tries` 합, `correctRate = (tries-wrong)/tries`, `tries===0`인 주제 제외, `lowSample = tries<5`, `correctRate` 오름차순.
  - `newSession(mode, questions, now) -> Current` — `{mode, ids, answers: Array(n).fill(null), idx: 0, secondsLeft: mode==="exam" ? 3600 : null, startedAt: now}`
  - `answer(cur, choice) -> boolean` — 현재 `idx`에 기록. 학습 모드에서 이미 답했으면 `false`, 실전 모드는 덮어쓰기 허용.
  - `restoreCurrent(cur, poolById) -> Current|null` — 없어진 ID와 그 답을 함께 제거, `idx` 범위 보정, 남은 문항 0이면 `null`.
  - `emptyRecord() -> {version:1, q:{}, sessions:[], current:null}`
  - `loadRecord(storage) -> Record` — 없음/파싱 실패/`version!==1`이면 `emptyRecord()`.
  - `saveRecord(storage, rec) -> boolean` — 예외를 잡아 `false`.
  - `addSession(rec, s) -> void` — 앞에 추가, 50개 초과분 삭제.
