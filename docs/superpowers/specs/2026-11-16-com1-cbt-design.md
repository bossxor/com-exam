# 컴활 1급 필기 CBT 연습 앱 — 설계

- 작성자: 오정택
- 날짜: 2026-11-16
- 상태: 승인됨 (2026-11-16)

## 1. 목적

컴퓨터활용능력 1급 필기는 문제은행식이다. 실제 기출과 비슷한 문제를 최대한 많이 반복해서 푸는 것이 합격 전략이다.
참고 사이트(https://com1-cbt-practice.computerbusan.chatgpt.site/)는 문제를 다 푼 뒤 한꺼번에 채점하거나 해설을 처음부터 보여 준다.
사용자는 **한 문제 풀고 → 바로 정답과 그 문항 해설 확인 → 끝나면 점수**의 흐름을 원한다.
또 참고 사이트 문제는 실제 시험(2026-11-13 응시)보다 쉬웠다. 그래서 실제 기출과 더 어려운 문제를 많이 넣는다.

사용자는 한 명(본인)이다. 웹 브라우저(PC)와 안드로이드 폰에 설치해서 쓴다.

## 2. 목표 / 비목표 / 반목표

**목표 (1차 버전, 기능 1~6)**
1. 학습 모드: 한 문제 답하면 즉시 정답/오답, 정답 번호, 해설 표시. 세트 끝나면 과목별 점수와 합격 판정.
2. 오답노트: 틀린 문제 자동 수집. 연속 2회 정답이면 빠진다.
3. 출제 범위 선택: 문제집(회차)별, 과목별, 출처별, 필터(전체 / 오답노트 / 별표 / 안 푼 문제), 문항 수, 순서(원래 순서 / 무작위).
4. 문항별 기록: 푼 횟수, 틀린 횟수, 별표(중요 문제).
5. 실전 모드: 60분 타이머, 해설 없이 풀고 종료 시 채점 후 문항별 해설 일괄 확인.
6. 취약 주제 통계: 주제 태그별 정답률 표시.
7. **이전 오답 표시** (사용자 추가 요청): 문제 화면에서 이전에 틀린 문제임을 표시한다. "이전 오답 N회" 배지와, 답을 확인한 뒤 "지난번 내 답" 표시.

**비목표**
- 실기 대비 (별도 프로젝트).
- 기기 간 기록 동기화, 백업/복원 (2차 버전 후보).
- 로그인, 서버, 다중 사용자.
- 앱 실행 중 AI 호출. 문제·정답·해설은 제작 단계에서 한 번 만들고 검수해 데이터 파일로 고정한다. 앱은 그 데이터를 모드별로 보여 주기만 한다.
- 플레이 스토어 배포.

**반목표 (이렇게 되면 실패)**
- 틀린 정답/해설이 들어가서 오답을 외우게 되는 것.
- 폰에서 전화가 오거나 앱을 닫았을 때 풀던 세트가 사라지는 것.
- 문제 추가 때마다 앱 코드를 고쳐야 하는 것.
- 저작권 문항을 공개 인터넷에 올리는 것.

## 3. 제약

- 문항 저작권은 대한상공회의소(기출)와 참고 사이트 제작자에게 있다. **개인 학습용으로만 쓴다.**
- **공개 범위 (사용자 결정: A안):** GitHub 저장소 `https://github.com/bossxor/com-exam`(공개)에는 앱 코드, 문서, 도구, AI 제작 문제집(`ai-*`)만 올린다. 기출(`kcci-*`, `kcci-old-*`)과 참고 사이트(`ref-*`) 문제집 파일, 그 그림, 원본(`pdf/`, `tools/src/`)은 `.gitignore`로 제외하고 로컬(`U:\`)에만 둔다.
  - GitHub Pages 웹앱 = AI 문제만 보인다.
  - 안드로이드 APK와 PC 로컬 실행 = 로컬 파일까지 전체 문제가 보인다 (APK는 로컬에서 빌드하므로 로컬 파일이 들어간다).
- 인터넷 기출 사이트를 자동으로 대량 수집(크롤링)하지 않는다. 대부분 이용약관이 금지한다. 추가 기출은 사용자가 PDF로 받아 `U:\pdf\`에 넣으면 같은 방식으로 변환한다.
- 작업 위치: 네트워크 드라이브 `U:\`.
- 설치된 도구: Node 24, Python 3.14, JDK 17/21, Android SDK(`C:\Android\Sdk`), adb, git. Android Studio는 없다(Gradle 명령줄 빌드).
- 시험 규칙: 과목당 20문항, 총 60문항, 60분. 합격 = 평균 60점 이상 **그리고** 과목별 40점 이상.

## 4. 접근 방식

| 방식 | 내용 | 판단 |
|---|---|---|
| **A. 웹앱 하나 + 안드로이드 WebView 껍데기** | 화면/로직 코드 1벌. 안드로이드 앱은 같은 웹 파일을 앱 안에 넣어 띄운다. | **선택.** 문제·기능 수정이 한 곳에서 끝난다. 오프라인 동작. |
| B. 네이티브 Compose 앱 + 별도 웹앱 | 같은 로직 2벌 | 작업량 2배, 두 앱 동작 불일치 위험. 거절. |
| C. Flutter / Compose Multiplatform | 코드 1벌, 도구 무거움 | 이 규모에 과함. 거절. |

데이터 출처도 정했다: 참고 사이트 1~7회(420문항) + PDF 기출 2회(120문항) + AI 제작 고난도 문항. 셋 다 쓴다.

## 5. 전체 구조

```
U:\
├─ pdf\                    원본 PDF (사용자 자료, git 제외)
├─ web\                    웹앱 = 안드로이드 앱 내용 (빌드 도구 없음)
│  ├─ index.html
│  ├─ style.css
│  ├─ core.js              순수 로직 (채점, 오답노트, 통계, 출제) — 테스트 대상
│  ├─ app.js               화면/이벤트
│  ├─ manifest.json        PWA 설치용
│  └─ data\
│     ├─ index.js          문제집 목록 (로드 순서)
│     ├─ ref-01.js … ref-07.js     참고 사이트
│     ├─ kcci-2024-01.js, kcci-2024-02.js   PDF 기출
│     ├─ ai-01.js …        AI 제작
│     └─ img\              그림 문항 이미지
├─ android\                Kotlin WebView 앱 (Gradle)
├─ tools\                  데이터 변환·검증 스크립트
├─ tests\                  core.js 단위 테스트 (node:test)
└─ serve.cmd               PC에서 웹앱 실행 (localhost)
```

### 5.1 데이터를 `.js` 파일로 두는 이유

JSON을 `fetch`로 읽으면 `file://` 환경과 안드로이드 `file:///android_asset/`에서 막힌다.
각 문제집을 `<script>`로 읽는 JS 파일로 두면 서버 없이도, 안드로이드에서도 그대로 동작한다.
문제 추가 = 데이터 파일 하나 추가 + `data/index.js`에 한 줄 추가. 앱 코드는 고치지 않는다.

## 6. 데이터 형식

문제집 파일 하나 = 문제집(회차) 하나.

```js
addBank({
  id: "kcci-2024-01",          // 영문/숫자/하이픈, 전역 고유
  title: "2024 상시 기출 01회",
  source: "kcci",              // "kcci"(2024 상시 기출) | "kcci-old"(2014~2020 정기 공개 기출) | "ref"(참고 사이트) | "ai"(AI 제작)
  questions: [
    {
      n: 1,                    // 문제집 안 번호 (1부터)
      subject: 0,              // 0 컴퓨터 일반, 1 스프레드시트 일반, 2 데이터베이스 일반
      topic: "network",        // 6.1 주제 목록의 키
      text: "문제 본문",
      choices: ["①", "②", "③", "④"],   // 정확히 4개, 번호 기호 없이 내용만
      answer: 2,               // 0~3
      explanation: "해설 (오답 보기 설명 포함 가능, 줄바꿈 \n 허용)",
      visual: "",              // 선택: 표 등 HTML 조각 (화이트리스트 태그만)
      image: ""                // 선택: "img/kcci-2024-01-23.png"
    }
  ]
});
```

- 문항 고유 ID = `${bank.id}-${n}`. 학습 기록의 키다. **한 번 배포한 문제집의 `id`와 `n`은 바꾸지 않는다.** 바꾸면 기록이 끊긴다.
- 문제집 하나는 과목별 20문항씩 60문항을 기본으로 한다. AI 문제집도 같다.
- `visual` HTML은 우리 데이터만 쓰지만 `table, tr, th, td, div, span, b, i, br, code, pre, img` 태그만 허용한다. 검증 스크립트가 확인한다.

### 6.1 주제 목록 (기능 6)

| 과목 | 키: 이름 |
|---|---|
| 0 컴퓨터 일반 | `windows`: Windows/운영체제, `hardware`: 하드웨어·CPU·기억장치, `software`: 소프트웨어·자료표현, `network`: 네트워크·인터넷, `security`: 정보보안, `multimedia`: 멀티미디어, `trend`: 최신 IT 용어 |

## 7. 화면과 흐름

### 7.1 홈 (출제 설정)

```
[컴활 1급 필기 CBT]
모드:   (●) 학습 모드  ( ) 실전 모드(60분)
문제집: [v] 기출 2024-01  [v] 기출 2024-02  [ ] 참고 1회 ... [ ] AI 1회 ...   (출처별 전체선택)
과목:   [v] 컴퓨터 일반  [v] 스프레드시트  [v] 데이터베이스
필터:   (●) 전체 ( ) 오답노트(37) ( ) 별표(5) ( ) 안 푼 문제(412)
문항수: (●) 전체  ( ) 20  ( ) 60  ( ) 직접 [  ]
순서:   (●) 원래 순서  ( ) 무작위
[시작]                         [이어서 풀기: 기출 2024-01, 23/60]   [통계]
```

- **기본값 = 섞어 풀기:** 모든 문제집 선택, 3과목, 과목별 20문항씩 무작위 60문항. 난이도별로 나눠 풀지 않는다 (사용자 결정: 섞어서 푼다). 문제집마다 출처 표시(기출 / 구 기출 / 참고 / AI)는 보여 주되 난이도 필터는 만들지 않는다.
- "과목별 20문항씩": 선택 범위에서 과목마다 따로 무작위로 뽑는다. 어떤 과목 문항이 20개보다 적으면 있는 만큼만 넣는다.
- 실전 모드를 고르면 같은 기본값에 60분 타이머가 붙는다. 바꿀 수 있다.
- 선택 결과가 0문항이면 시작 버튼을 막고 "조건에 맞는 문제가 없습니다"를 표시한다.

### 7.2 문제 화면 — 학습 모드

```
기출 2024-01 · 컴퓨터 일반 · 12/60         [☆ 별표]   [그만 풀기]
[이전 오답 2회]                                ← 오답 기록이 있을 때만
12. 다음 중 ... 옳지 않은 것은?
(표/그림)
 ① ...
 ② ...   ← 누르면 즉시 채점
 ③ ...
 ④ ...
---- 답한 뒤 ----
 ② ...  ✗ 내 답
 ③ ...  ✓ 정답
 ① ...  · 지난번 내 답            ← 이전 기록의 마지막 선택이 있고, 이번 답과 다를 때
[해설] 포털 사이트는 ...
                                    [다음 문제 →]
```

- 한 번 답하면 그 문항은 바꿀 수 없다 (학습 모드). 바로 기록에 반영한다.
- 마지막 문제 뒤에 결과 화면.
- 문제 번호 목록(진행 현황 격자)은 넣지 않는다. 학습 모드는 순서대로 푼다.

### 7.3 문제 화면 — 실전 모드

- 남은 시간 표시. 이전/다음 이동, 답 변경 가능. 번호 격자로 이동 가능 (답함/안 함 표시).
- 정답과 해설은 숨긴다. "이전 오답" 배지도 숨긴다 (실전 조건).
- 시간이 0이 되거나 [제출]을 누르면 채점한다. 안 푼 문항은 오답으로 친다.
- 채점 뒤 결과 화면 + 문항별 해설 목록 (내 답, 정답, 해설, 틀린 것만 보기 토글).

### 7.4 결과 화면

```
총점 평균 58.3점 — 불합격 (평균 60 미만)
컴퓨터 일반      75점 (15/20)
스프레드시트     35점 (7/20)   ← 과락 (40 미만)
데이터베이스     65점 (13/20)
이번에 틀린 문제 25개 → [틀린 문제 다시 풀기]   [홈]
```

- 점수 = 과목별 (정답 수 ÷ 그 과목 출제 수 × 100), 소수 첫째 자리 반올림.
- 평균 = 출제된 과목 점수의 산술 평균.
- 합격 판정은 3과목이 모두 출제된 경우에만 표시한다. 일부 과목만 풀었으면 점수만 표시한다.
- [틀린 문제 다시 풀기] = 이번 세트에서 틀린 문항으로 새 학습 모드 세트를 연다.

### 7.5 통계 화면 (기능 6)

- 주제별 정답률 표: 주제명, 푼 횟수, 정답률. 정답률 낮은 순으로 정렬. 5회 미만은 "표본 적음"으로 흐리게 표시.
- 과목별 누적 정답률.
- 최근 세트 기록 10개: 날짜, 문제집, 모드, 과목별 점수, 합격 여부.
- 주제 행을 누르면 그 주제 문제만으로 학습 모드 세트를 시작한다.

## 8. 학습 기록 (localStorage)

키 `com1.v1` 하나에 JSON으로 저장한다.

```js
{
  version: 1,
  q: {                                  // 문항 ID → 기록
    "kcci-2024-01-12": { tries: 3, wrong: 2, streak: 1, star: false, lastChoice: 1, lastAt: 1794786530000 }
  },
  sessions: [                           // 끝난 세트, 최근 50개만 보관
    { at, mode: "study"|"exam", bankIds: [...], scores: [75, 35, 65], counts: [20,20,20], passed: false }
  ],
  current: null | {                     // 진행 중인 세트 (이어서 풀기)
    mode, ids: [...], answers: [null|0..3], idx, secondsLeft, startedAt
  }
}
```

- **오답노트 포함 조건:** `wrong > 0 && streak < 2`. 정답이면 `streak + 1`, 오답이면 `streak = 0`이고 `wrong + 1`.
- **이전 오답 배지:** `wrong > 0`이면 "이전 오답 N회". 현재 세트에서 방금 기록한 결과는 배지 계산에서 뺀다 (화면에 들어올 때의 값을 쓴다).
- **기록 반영 시점:** 학습 모드는 답할 때마다, 실전 모드는 채점할 때 한꺼번에.
- **진행 저장:** 답할 때마다, 그리고 실전 모드 타이머는 10초마다 `current`를 저장한다. 앱을 닫은 동안 타이머는 멈춘다: 복구할 때 `secondsLeft`를 그대로 쓴다 (팀장 결정).
- 필터(오답노트, 별표, 안 푼 문제)와 [틀린 문제 다시 풀기]는 두 모드에 모두 쓸 수 있다. 다시 풀기 세트는 원래 세트의 모드를 따른다. 앱을 다시 열면 홈에 [이어서 풀기]가 보인다. 새 세트를 시작하면 기존 `current`를 덮어쓰기 전에 확인을 묻는다.
- 데이터 파일에서 사라진 문항 ID의 기록은 무시한다 (지우지 않는다).
- 저장소 쓰기 실패(용량 초과 등) 시 화면 상단에 "기록 저장 실패" 알림을 띄운다. 조용히 넘어가지 않는다.
- PC 웹과 폰 앱의 기록은 따로다. 동기화는 비목표다.

### 9.3 AI 제작 고난도 문제
- 목표: 1차로 **7회분(420문항)**, 회차당 과목별 20문항. 실제 2024 기출 수준 이상으로 만든다: 보기 4개가 모두 그럴듯함, 함수 결과·SQL 결과·진법 계산 같은 계산형 비중을 높임, Office 2021 / Windows 10 기준.
- 문제 본문이나 해설을 기출에서 그대로 베끼지 않는다. 기출의 출제 범위와 형식만 따른다.
- **검수 (필수):** 만든 세션과 다른 팀원 세션이 정답을 가린 채 풀어서 답을 낸다. 제작자 정답과 다르면 팀장이 판정한다. 판정이 애매한 문항은 버린다.
- 한 회차 완성 → 검수 → 등록 순서로 한 회차씩 진행한다. 7회 이후 추가 생산 여부는 사용 후 결정한다.
- 정답 판정자는 팀장 세션이다. 사용자는 판정에 참여하지 않는다 (팀장 결정).
- **릴리스 순서 (팀장 결정):** 앱(기능 1~7)은 기존 540문항(참고 420 + 기출 120)으로 먼저 완성·설치한다. AI 문제집은 검수가 끝난 회차부터 추가한다. 앱 완성은 AI 문제 제작을 기다리지 않는다.

### 9.3a 출제 비중 (사용자 시험 경험 반영)
- 사용자가 2026-11-13 실제 시험에서 세 과목 모두 어려웠고, **스프레드시트 일반 점수가 가장 낮았다.** SQL은 익숙해서 어렵지 않았다.
- AI 정규 회차(7회)는 실제 시험처럼 과목별 20문항을 지킨다. 그 안에서:
  - 스프레드시트: 함수 결과 계산(중첩 함수, 배열 수식, 날짜·텍스트 함수), 데이터 분석(목표값 찾기, 시나리오, 데이터 표, 통합), 피벗 테이블·부분합, 매크로·VBA 코드 결과, 차트 세부 옵션, 고급 필터 조건 비중을 높인다. 기본 서식·입력은 줄인다.
  - 데이터베이스: SQL 단순 문법은 회차당 3문항 이하. 폼·보고서 속성, 매크로, 정규화, 관계·참조 무결성, 쿼리 종류(크로스탭·실행 쿼리) 비중을 높인다.
  - 컴퓨터 일반: Windows 10 설정, 네트워크·보안, 최신 IT 용어를 2024 기출 수준 이상으로.
- **스프레드시트 추가 문제집 3개:** `ai-xl-01`~`ai-xl-03`, 각 60문항 전부 스프레드시트. 정규 7회와 같은 검수를 거친다. 목적은 스프레드시트 문항 풀을 넓혀서 섞어 풀기를 반복해도 같은 문제가 덜 나오게 하는 것이다. 스프레드시트만 따로 푸는 전용 버튼은 만들지 않는다 (사용자: 스프레드시트만 풀고 싶지는 않다). 과목 선택은 홈의 과목 체크로 충분하다.
- **쉬운 문제도 뺄 생각이 없다 (사용자 결정).** 참고 사이트 문항을 포함한 모든 문제집이 섞어 풀기 기본 범위에 들어간다.

### 9.3c "헷갈림"을 만드는 출제 방식
사용자가 실제 시험에서 겪은 어려움은 "전혀 모른다"보다 "보기가 헷갈린다"였다. AI 문항은 이 점을 노린다.
- 오답 보기는 정답과 한 단어, 한 인수, 한 조건만 다르게 만든다. 예: `VLOOKUP`의 범위 조회 인수 TRUE/FALSE, `DSUM` vs `SUMIFS` 인수 순서, `COUNT` vs `COUNTA`, 상대/절대 참조 복사 결과, 폼 속성 "기본 보기" vs "레코드 원본".
- "옳은 것" / "옳지 않은 것" 문항을 섞고, 보기 4개가 모두 그럴듯한 설명이 되게 한다.
- 비슷한 용어 쌍을 일부러 함께 낸다 (예: 캐시/가상 메모리, 게이트웨이/라우터/브리지, 목표값 찾기/시나리오/데이터 표).
- 해설에는 정답 이유뿐 아니라 **헷갈리는 오답 보기마다 왜 틀렸는지**를 한 줄씩 쓴다. 2024 기출 해설의 `<자세한 설명>` 방식과 같다. 헷갈림을 줄이는 것이 해설의 목적이다.

### 9.3b 인터넷 공개 기출 (조사 결과, 2026-11-16)
- 2021년 이후 상시 시험 원본은 공식 공개되지 않는다. 최신 회차는 출판사 수험서(복원 기출)로만 나온다.

### 9.4 검증 스크립트 `tools/validate.mjs`
`node tools/validate.mjs`가 `web/data/`의 모든 문제집을 읽어 검사한다. 하나라도 실패하면 종료 코드 1.

### 10.1 화면 디자인 방향

**콘셉트: 문제지와 OMR 답안지, 그리고 채점 펜.** 시험을 보는 사람이 매일 보는 물건에서 시각 언어를 가져온다. 화려한 장식 대신 "채점되는 순간" 하나만 기억에 남게 한다.

- 문제 본문과 보기는 시험 문제지처럼 명조(세리프)로 쓴다. 버튼·메뉴·숫자 같은 앱 요소는 고딕(산세리프)으로 쓴다. 두 서체의 역할을 섞지 않는다.
- 보기 번호는 OMR 답안지의 마킹 칸처럼 연분홍 테두리 원으로 그린다. 고르면 컴퓨터용 사인펜처럼 검게 칠해진다.
- **기억에 남을 한 가지 = 채점 표시.** 답하면 정답 번호에 손으로 그린 듯한 빨간 동그라미가 한 번 그려진다(약 300ms). 틀린 내 답에는 빨간 빗금이 그어진다. 선생님이 빨간 펜으로 채점하는 모습이다. 이것 말고 다른 장식 애니메이션은 넣지 않는다. `prefers-reduced-motion`이면 바로 표시한다.
- 해설은 문제지 여백에 적은 빨간 펜 메모처럼 왼쪽에 빨간 세로줄을 둔 블록으로 표시한다.
- 진행 표시는 OMR 답안지 가장자리의 타이밍 마크(짧은 검은 눈금)를 쓴다. 푼 문항은 검게, 틀린 문항은 빨갛게, 안 푼 문항은 연하게 표시한다. 그래서 장식이 아니라 진행 정보다.
- 카드 묶음, 그림자, 그라데이션은 쓰지 않는다. 구분은 여백과 가는 선으로 한다.

- 두 서체 모두 woff2로 `web/fonts/`에 넣는다. 파일은 구현 단계에서 공식 배포처에서 받는다 (받기 전에 사용자 확인).

**레이아웃**
- 모바일 우선, 한 단. 본문 최대 폭 680px, 왼쪽 정렬. PC에서는 가운데 배치만 하고 2단으로 나누지 않는다.
- 보기 한 줄 = 마킹 칸(28px 원) + 보기 글. 줄 전체를 누를 수 있고 높이는 최소 56px.
- [다음 문제] 버튼은 화면 아래에 고정한다. 엄지로 누르기 쉽다.

**접근성·조작 기준 (UI UX Pro Max 점검):**
- 하단 고정 버튼과 상단 영역은 `env(safe-area-inset-*)`만큼 띄운다 (폰 제스처 바, 노치).
- 채점 결과(정답/오답)는 `aria-live="polite"` 영역으로 읽어 준다. 보기는 `button`, 마킹 상태는 `aria-pressed`.
- 키보드 포커스 표시를 지우지 않는다. PC에서는 숫자키 1~4로 답하고 Enter로 다음 문제.
- 글자 크기는 브라우저/시스템 확대를 따른다 (`rem` 단위, 확대 막지 않음).
- 참고: 디자인 DB 검색 결과(클레이모피즘, Comic Neue, 보라색)는 어린이 학습앱용이라 성인 시험 대비에 맞지 않아 쓰지 않았다.

**문구 원칙:** 버튼은 하는 일을 그대로 쓴다 ("다음 문제", "채점하기", "틀린 문제 다시 풀기"). 빈 화면은 할 일을 알려 준다 ("오답노트가 비었습니다. 문제를 풀면 틀린 문제가 여기 모입니다."). 오류는 무엇이 잘못됐고 어떻게 하면 되는지 말한다.

**기본값을 피한 점 (검토 기록):** 첫 안은 남색 상단바 + 흰 카드 + 파란 강조였다. 참고 사이트와 거의 같고, 어느 시험 앱에나 쓸 법한 모양이라 버렸다. 크림색 배경 + 테라코타 강조도 흔한 기본값이라 피했다. 종이는 차가운 흰색으로 두었다.

## 11. 안드로이드 앱

- Kotlin, Activity 1개, `WebView` 1개. 패키지 `com.songwol.com1cbt` (팀장 결정), 앱 이름 "컴활1급 CBT".
- `minSdk 24`, `targetSdk`는 설치된 SDK의 최신 플랫폼.
- Gradle `sourceSets`에서 `../web` 폴더를 assets로 쓴다. 웹 파일을 복사하지 않는다.
- `file:///android_asset/index.html`을 연다. `javaScriptEnabled`, `domStorageEnabled` 켠다. 인터넷 권한은 넣지 않는다.
- 뒤로 가기: 웹앱의 `window.appBack()`을 호출한다. 웹앱이 홈 화면이면 `false`를 돌려주고, 그때 앱을 닫는다. 문제 풀이 중이면 웹앱이 "그만 풀까요?"를 묻는다.
- 화면 회전·다크 모드 전환 때 WebView가 다시 만들어져도 풀던 세트는 8장의 `current`로 복구된다.
- 결과물: 디버그 APK. `adb install`로 폰에 설치한다. 스토어 서명은 비목표.
- **네트워크 드라이브 대응 (팀장 결정):** `U:\`는 네트워크 드라이브라 파일 잠금 오류가 실제로 난다 (설계 중 `EBUSY: resource busy or locked, fchmod` 확인). 소스는 `U:\android\`에 두되, Gradle 빌드 출력(`buildDir`)과 Gradle 캐시(`GRADLE_USER_HOME`)는 로컬 디스크 `%LOCALAPPDATA%\com1cbt-build\`로 돌린다. 빌드 뒤 APK를 `U:\dist\com1cbt.apk`로 복사한다. `dist/`는 git에서 제외한다. 파일 편집 도구가 같은 오류로 실패하면 스크립트로 파일을 다시 쓴다.

## 12. 테스트와 검증

- `node --test tests/`: `core.js` 단위 테스트. 채점(반올림, 과락, 일부 과목 판정 생략), 오답노트 진입/이탈(연속 2회), 이전 오답 배지 값, 필터 조합, 주제 통계.
- `node tools/validate.mjs`: 데이터 전체 검증.
- 브라우저 확인: PC Chrome에서 학습 모드 1세트, 실전 모드(타이머 짧게 바꿔서) 1세트, 이어서 풀기, 통계 화면.
- 실제 기기: 사용자 폰 있음, USB/무선 디버깅 가능. APK 설치 → 실행 → 문제 풀이 → 앱 종료 후 재실행해 이어서 풀기 → 뒤로 가기 동작 → 스크린샷. 기기가 연결되지 않으면 검증 못 한 항목으로 보고한다.

## 13. 팀 운영 (구현 단계)

- 팀장: 이 세션 (Opus 5.5). 계획, 작업 배분, 결과 검토, 정답 판정, 커밋 확인.
- 팀원 세션 (Sonnet 5.5): 정답 정확성이 중요한 데이터 작업이 많아 Haiku 대신 Sonnet을 쓴다.
  - 데이터: 참고 사이트 변환 + 주제 태그 / PDF 변환 / AI 문제 제작 / AI 문제 검수(제작과 다른 세션)
  - 앱: 웹앱(`core.js` + 화면) / 안드로이드 껍데기
- 팀원 세션은 병렬로 돌린다 (사용자 요청). 계획은 독립 작업 단위로 나누고, 작업마다 파일 소유권을 적는다.

- git: `U:\`를 저장소로 만들고 원격 `origin = https://github.com/bossxor/com-exam`(기본 브랜치 `main`)에 연결한다. 작업 단위별 커밋 후 푸시한다. 푸시 전에 `git ls-files`에 3장의 제외 대상이 하나도 없는지 확인한다.

## 15. 팀장이 정한 것 (사용자 확인 필요)

- 웹앱: GitHub Pages(AI 문제만) + PC 로컬 서버(전체).
- AI 문제 1차 목표: 정규 7회분 420문항 + 스프레드시트 집중 3회분 180문항.

- 실전 모드에서 이전 오답 배지 숨김.
- 데이터 파일 형식은 JSON이 아니라 JS(`addBank`).

- 실전 모드 이어서 풀기: 앱을 닫은 동안 타이머 정지.
- Gradle 빌드 출력은 로컬 디스크, APK는 `U:\dist\`로 복사.
